# Make targets

Every target runs as `make -C modernization <target>`. "Passes" means exit status 0; every target prints one summary line, `<target>: OK` or `<target>: FAILED (<reason>)`. The targets that exist today keep their behaviour; the stubs are replaced when their phase lands ([overview.md](overview.md#phasing)).

## Lifecycle

| Target | What it does | Passes when |
| :-- | :-- | :-- |
| `setup` | Checks JDK 21, Node 24, Docker/Colima and the Airflow venv, creates `.env` with generated secrets, writes the absolute `CARDDEMO_VAR_DIR` into `.env` when it is missing or empty (add-only; a relative value or a removed output setting is a `FAIL` line, [contract](batch-execution-contract.md#410-output-root-ruled-2026-11-11) section 4.10), checks that `CARDDEMO_VAR_DIR` and the report staging base carry no inheritable ACL entry for another principal (`ls -led` on macOS, `getfacl` on Linux where installed; a `FAIL` line, a higher ancestor only a `WARN` line, [contract](batch-execution-contract.md#instance-and-root) section 4.10, limit A-1; owner infra), validates the compose file; later also runs `npm ci`, installs `carddemo_airflow` into the venv and warms the Maven cache. | every check prints `ok` and it ends with `setup: OK` (exists today). |
| `db-reset` | Starts SQL Server if needed, drops and recreates the `carddemo` database, and runs every Flyway migration through `db-migrate` (schemas, tables, logins, grants, views). The reference rows come from `load`. The migrations give the new database a new instance ID (`ops.database_instance`), so it writes into a new, empty instance root `<CARDDEMO_VAR_DIR>/out/<sha256 of the database name>/<instance_id>/`, which db-migrate creates with its marker. Outputs of earlier instances are kept and never read. They are listed with their file counts, and never deleted or moved ([contract](batch-execution-contract.md#410-output-root-ruled-2026-11-11) section 4.10). | Flyway reports every migration applied, `flyway validate` is clean, each service login can connect and is refused a table outside its grants, the marker row and the instance root with its `.instance` file exist, and any earlier instance root is unchanged. |
| `db-migrate` | Creates the database when it is missing and applies new migrations without dropping it, then ensures the instance root and its marker (exists today, apart from the root). `NEW_INSTANCE=1` also gives the database a new instance ID and root, after a restore or copy ([contract](batch-execution-contract.md#410-output-root-ruled-2026-11-11) section 4.10). Earlier roots are listed with their file counts and never deleted or moved. | as `db-reset`, without dropping the database. |
| `load` | Runs `dataLoadJob` on `app/data/ASCII` (and the authorization sample unload when the module is enabled), then restarts `core.tran_id_seq` with `9000000000000000` when no loaded `tran_id` is reserved (16 digits starting with `9`), and otherwise with the highest reserved loaded ID plus 1 ([batch.md](batch.md#transaction-ids-from-the-file-and-from-the-services)). On the sample the first generated ID is `9000000000000000`. Users are seeded by `identity-service`, not by `load`. | every step ends `COMPLETED` with the expected counts in [data-model.md](data-model.md#sample-data-migration) (50 accounts, customers, cards, cross-references and category balances; 7 types, 18 categories, 51 disclosure groups). |
| `up` | Runs the ACL preflight of `setup` (limit A-1) and refuses to start on a `FAIL` line, then starts the infrastructure (as today), then the converted services, `batch-service`, Airflow and the web app on 127.0.0.1, and waits for their health checks. | every container and process reports healthy within `UP_TIMEOUT`, and `make status` lists them. |
| `smoke` | Read-only check of the running stack: health endpoints, sign-on as a seed user, `GET /api/auth/me`, a Bill Pay balance preview, the DAG list without import errors, the RabbitMQ queues of the enabled modules. | every check passes in under 60 seconds and no table row count changes. |
| `billpay` | Starts only the Bill Pay slice (SQL Server, `identity-service`, `billpay-service`, web), runs `db-reset` and `load` if the database is empty, runs one scripted sign-on, preview and payment, then leaves the slice running at `http://127.0.0.1:25173/bill-pay`. | the slice is healthy and the scripted payment returns `Payment successful.  Your Transaction ID is ...` with the account balance at zero afterwards. |
| `down` | Stops the web app, Airflow, the JVMs and the containers; data volumes are kept (as today for the containers). | no `carddemo-modern` container and no process recorded in `var/run/` is left running. |

## Verification

| Target | What it does | Passes when |
| :-- | :-- | :-- |
| `verify-spec` | Checks the NL spec format and coverage, builds the GnuCOBOL batch programs and runs every spec-only reimplementation in `docs/modernization/spec/checks/` (exists today). | `check_spec.py` reports no finding and every reimplementation matches the GnuCOBOL output on sample and stress data. |
| `verify-ledger` | Compares `ledger/*.toml` with the code and the spec. | every switch read through `FidelitySwitches` has a ledger entry, every entry names a defect-decide item the spec defines, every `fixed` value and every deviation has an approver and a date, and every architecture-dependent item has a deviation entry. |
| `test-backend` | `./mvnw verify`: unit, service integration (Testcontainers), contract and ArchUnit tests for the platform libraries, every converted service and `batch-service`, in both fidelity modes. | zero failing or erroring tests; JUnit reports are written to `build/test-results/backend/`. |
| `test-billpay` | The Bill Pay subset: `billpay-service` and `ledger-core` tests, scenarios S1 to S12 against the API, the screen's Vitest tests and its Playwright tests. | all of them pass, and every BR, VAL, FLOW, SE, ERR and NUM item of unit BILL has a passing test. |
| `verify-batch` | The differential harness: each converted batch job against its GnuCOBOL program on sample and stress data ([batch.md](batch.md#differential-verification)). | in legacy mode every exported record and report line is byte-identical; in fixed mode the only differences are in the records the switched item describes. |
| `verify-data` | Reconciles the demo database with the source files after `load` ([data-model.md](data-model.md#reconciliation)). It changes nothing. The independent data-load oracle is not part of it: it runs in `verify-batch-spec`. | counts, key sets, control totals, byte-for-byte re-export and the cross-table checks report zero mismatches for every table. |
| `verify-harness` | Self-test of the differential harness with seeded differences. | identical inputs compare equal, every seeded difference (byte, missing record, order, sign) is reported, and only wall-clock timestamps are masked. |
| `verify-cycle` | On a fresh `load`, triggers `carddemo_daily_cycle` through the Airflow API for business date 2022-07-06, then a second trigger of the same date and a run for the next date. | the first run succeeds with the end state equal to the GnuCOBOL F-order run of the harness, the repeated trigger is refused without changing data, the window is closed at the end, the next-date run succeeds, and the crash-recovery checks of [batch.md](batch.md#restart-and-idempotency) pass. |
| `test-airflow` | pytest on the DAGs without a running Airflow: `DagBag` import, task order, parameters, pool and `max_active_runs`, the import rule, the operator against a stub `batch-service`. | zero DAG import errors and every test passes. |
| `web-build` | `npm ci`, client generation from the OpenAPI documents, `tsc --noEmit`, ESLint, Vitest, `vite build`. | no type or lint error, every Vitest test passes, and `web/dist/` is written within the bundle-size budget in `package.json`. |
| `test-e2e` | Playwright against the stack from `make up` on fresh data: each converted screen's equivalence scenarios, keyboard-only paths and axe accessibility checks. | every test passes in Chromium (CI nightly adds Firefox and WebKit) with no serious or critical axe finding. |
| `trace` | Builds the traceability matrix from the spec, the test reports and the ledger ([repo-build-ci.md](repo-build-ci.md#traceability)). | no gap for the units in `ledger/scope.toml` and no test cites an unknown item ID. |

## Proposed additions

These targets are not in today's `Makefile`; the batch design needs them.

| Target | What it does | Passes when |
| :-- | :-- | :-- |
| `batch-window-close` | Closes a batch window left open after a failed cycle, once the operator has recovered (replaces running OPENFIL by hand). The cycle stays `OPEN`, so the next DAG run resumes it. | the `ops.batch_window` row is closed and the online services accept writes again. |
| `verify-batch-spec` | The spec-only validators of the catalogue jobs that `verify-batch` does not compare ([batch.md](batch.md#spec-only-validators-2026-11-11)), through two entry points in one private verify session, on the private database and under the lock of `verify-batch` (`CARDDEMO_VERIFY_BATCH_DB_NAME`): the job validators of PRTCATBL, TRANBKP, the authorization purge and DISCGRP, then the independent data-load oracle, which loads and resets that database for each case. Neither touches the demo database. Expected results come from the spec and the decisions, never from the jobs' output. A missing prerequisite (a jar, `.env`, the switch list, the lock) or a refused fixture login (batch.md, Fixture login) fails the run, never skips it. Exit status 0 `OK`, 1 `FAILED`, 2 usage error, 3 `PARTIAL`: `ONLY=<jobs>` (any of `PRTCATBL`, `TRANBKP`, `PURGE`, `DISCGRP`, `DATALOAD`) ends `PARTIAL`, exit 3, even when every selected case passed. | every case of both entry points passes in legacy and in fixed mode, and the PII scan finds no sentinel. |
| `cycle-rerun CYCLE=<id>` | Restores the account and category-balance snapshots taken before the cycle's posting step and reruns the cycle as a new job instance (replaces the runbook restore). | the snapshot restore and the rerun both succeed and the cycle's end state equals the first successful run of that input. |
